## Замечания, требующие действия

### F-1 — P2: отделить заявление об остановке стека от сохранённого evidence

Место: `/Users/zenalark/PycharmProjects/Test-java/getting-started-python/docs/qa-workflow/handoffs/07-integration.md:87`.

Handoff утверждает, что `compose down` выполнен и отсутствие контейнеров/сети
проверено. Однако `artifacts/integration/catupdval/final-state.txt:1` —
снимок **до** down: в нём работающие сервисы, а строки 16–19 связывают
живой gateway с fix image. Среди сохранённых integration-файлов нет
вывода/exit code down и проверки ресурсов после него. Поэтому независимое
ревью подтверждает fixture cleanup, но не историческое уничтожение всего
окружения и пользователей.

Действие координатору: обозначить down как сообщение исполнителя без
сохранённого подтверждения; не ссылаться на pre-down снимок как доказательство
его завершения. Если имеется исходный лог, приложить его. Проверка состояния
сейчас может быть отдельным новым наблюдением, но не восстанавливает
историческое доказательство. Повторный старт стенда для этого не требуется.
В следующем прогоне сохранить timestamps, команды, exit codes и post-down
выборки контейнеров/сетей пилота.

Влияние: не отменяет результаты API или удаление категорий; ограничивает
заявление о полностью доказанном lifecycle окружения при внешней передаче.

### F-2 — P2: не выдавать частичную привязку версии за полную per-run provenance

Место: `/Users/zenalark/PycharmProjects/Test-java/getting-started-python/docs/qa-workflow/handoffs/07-integration.md:54`;
связанный manifest:
`/Users/zenalark/PycharmProjects/Test-java/getting-started-python/artifacts/harness/run-3zbyks5d/manifest.json:8`.

Оба API manifest сохраняют SHA тестового репозитория и `dirty=true`, но
не хеши/копии незакоммиченных API-исходников, build/patch identity или
фактический image ID обслуживающего gateway во время каждого запуска.
Image inspect подтверждает существование двух разных образов; final-state
связывает fix image с работающим контейнером **после** API-прогона.
Аналогичная сохранённая runtime-привязка base к его execution отсутствует.
Логи сборки/аттестация, связывающие образ с исходниками base/patch, также
не входят в перечисленный пакет 07. Часть этой цепочки заявлена исполнителем,
а не независимо восстановлена из пакета.

Архив хешей 06 `artifacts/harness/run-tr1ho9aw/api-source-identity.json`
совпал со всеми восемью текущими файлами. Это поддерживает отсутствие
изменений с 06 до ревью, но не является snapshot каждого API execution.
Allure подтверждает одинаковые четыре негативных параметра и ожидаемую
семантику шагов в обоих прогонах; побайтовая неизменность во время двух
исторических запусков из их manifests не устанавливается.

Действие координатору: сохранить это ограничение при приёмке 07. Для
следующего execution добавить source identity для tests/fixtures/transport/
consts, ссылку на base + patch, построенный image ID и live container image
ID до/после запуска в отдельный execution manifest. Не дописывать текущие
хеши задним числом как измеренные во время прошлого прогона. Для внешнего
пакета либо явно принять ограничение, либо сделать новый подтверждённый
прогон после подготовки такого манифеста.

Влияние: не опровергает наблюдаемое red/green; ограничивает точную
воспроизводимость и независимо доказанную привязку результата к сборке.
