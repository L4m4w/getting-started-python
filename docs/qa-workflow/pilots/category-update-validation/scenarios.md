# Сценарии: валидация обновления категории

Пилот: `CAT-UPD-VAL`, версия сценариев: `1`, дата: 2026-11-14.
Источник ожиданий: [requirement.md, R1–R4](requirement.md).
Статус: подготовлено для ревью; автоматизация и прогоны не выполнены.
TestOps ID пока не назначены; локальные ID ниже сохраняются при синхронизации.

## Общие предусловия и данные

1. Запущена изолированная сборка приложения с известным SHA и gateway URL.
2. Есть выделенный пользователь и валидная авторизация этого пользователя.
3. Для каждого параметра создана отдельная категория с валидным исходным
   именем, отличающимся от целевого. Подготовка не должна исчерпывать лимит
   активных категорий или создавать дубликаты имён в пределах аккаунта.
4. Перед PATCH выполнить `GET /api/categories/all` с `excludeArchived=false`,
   найти категорию по `id` и сохранить snapshot `id/name/username/archived`.
5. В PATCH передать `id`, новое `name` и исходный `archived`; остальные поля
   тела, если нужны клиенту, заполнять из snapshot. Меняется только `name`.

Каждый параметр независим. После выполнения fixture удаляет созданные данные
доступным и подтверждённым способом. Публичного endpoint удаления категории
в просмотренном контроллере нет: до запуска нужно определить fixture очистки
через БД изолированного стенда либо пересоздание его данных. Архивация не
считается удалением. Использование общего публичного аккаунта не планируется.

## Обязательные случаи

Уровень: публичный REST API через gateway. Приоритет: высокий для всех случаев.
Значение `A × N` обозначает строку из N ASCII-букв `A`.

| Scenario ID | Новое имя | Требование | Ожидаемый ответ | Проверка повторным чтением |
| --- | --- | --- | --- | --- |
| CAT-UPD-VAL-001 | Пустая строка `""` | R1, R3 | HTTP 400 | Snapshot не изменён |
| CAT-UPD-VAL-002 | Три пробела `"   "` | R1, R3 | HTTP 400 | Snapshot не изменён |
| CAT-UPD-VAL-003 | `A × 1` | R2, R3 | HTTP 400 | Snapshot не изменён |
| CAT-UPD-VAL-004 | `A × 51` | R2, R3 | HTTP 400 | Snapshot не изменён |
| CAT-UPD-VAL-005 | `A × 2` | R2, R4 | HTTP 200 | Имя в точности переданное; остальные поля сохранены |
| CAT-UPD-VAL-006 | `A × 50` | R2, R4 | HTTP 200 | Имя в точности переданное; остальные поля сохранены |

Обычная кириллица может быть добавлена как дополнительная регрессия после
основных границ; специальные Unicode-случаи не подразумеваются этими данными.

## Два параметризованных автотеста

**`test_update_category_rejects_invalid_name`**: случаи 001–004.

1. Подготовить собственную категорию и получить snapshot.
2. Выполнить PATCH с параметром имени.
3. Проверить HTTP 400. Точный текст и порядок ошибок не фиксировать.
4. Повторно получить категории и найти прежний `id`.
5. Сравнить четыре поля со snapshot. Ответ PATCH без повторного чтения
   не доказывает неизменность данных.

**`test_update_category_accepts_name_at_length_boundary`**: случаи 005–006.

1. Подготовить собственную категорию и получить snapshot.
2. Выполнить PATCH с именем длиной 2 либо 50.
3. Проверить HTTP 200 и соответствие возвращённой категории целевому `id/name`.
4. Повторным GET подтвердить точное сохранение имени и неизменность
   `id`, `username`, `archived` относительно snapshot.

Fixtures выполняют очистку и при падении assertions. Не добавлять retries или
ослабление проверок для успешного прогона. Расположение тестов и импорты API-клиента
будут определены планом автоматизации после оценки существующего фреймворка.

## План проверки силы и артефакты

Сначала выполнить неизменённые сценарии на base, затем на head исправления
с одинаковой конфигурацией и свежими данными. Все результаты, включая
неожиданные статусы и ошибки setup/teardown, сохраняются без переобозначения PASS.
Если ни один негативный случай не показывает различие, проверить гипотезу
и окружение; не заявлять воспроизведение по одному чтению исходников.

Сохранить SHA приложения/тестов, URL окружения без credentials, команды,
execution ID, HTTP status и очищенные от секретов ответы, результаты повторного
GET, Allure/JUnit, результат очистки и ссылки на TestOps/MR после их появления.
