# Валидация имени при обновлении категории

ID: `CAT-UPD-VAL`. Версия: `1`. Дата: 2026-11-14.
Статус: пилот выбран пользователем; документ подготовлен для ревью,
автотесты и проверка поведения ещё не выполнены.

## Источник ожидаемого поведения

Пользователь принял предложенный пилот в обсуждении QA workflow. Базовое
требование из обсуждения: при переименовании имя категории содержит от 2 до 50
символов включительно и не состоит только из пробелов; невалидный запрос
возвращает HTTP 400 и не меняет сохранённые данные. Это источник ожиданий;
наблюдения исходного кода ниже описывают реализацию, а не заменяют требование.

Связанные материалы: [обследование](../../../plans/qa-workflow-discovery.md),
[план MVP](../../../plans/qa-workflow-mvp.md), [сценарии](scenarios.md).

## Область изменения

Публичный REST endpoint `PATCH /api/categories/update` в `niffler-gateway`.
Запрос выполняется авторизованным владельцем существующей категории.
В пилоте меняется только `name`, остальные поля передаются с исходными значениями.

| ID | Требование | Критерий приёмки |
| --- | --- | --- |
| R1 | Имя не может быть пустой строкой или состоять только из обычных пробелов U+0020 | HTTP 400; категория не изменена |
| R2 | Длина непустого имени — 2–50 включительно | 1 и 51 отклоняются с HTTP 400; 2 и 50 допускают обновление |
| R3 | Невалидное обновление не меняет сохранённую категорию | Повторное чтение возвращает прежние `id`, `name`, `username`, `archived` |
| R4 | Валидное имя сохраняется для той же категории | Повторное чтение по `id` возвращает переданное имя; `id`, владелец и `archived` сохранены |

Для однозначных границ в MVP используются имена из ASCII-букв без пробелов.
Проверка успешного ответа планируется как HTTP 200 по текущему контракту
контроллера; отдельное новое требование к формату успешного ответа не вводится.
Точный текст ошибки и порядок сообщений валидации не являются критерием MVP.

## Предположения и открытые вопросы

| Тема | Решение для пилота |
| --- | --- |
| Пробелы по краям | Не задаём trim/нормализацию; имена вида `" AB "` вне проверяемого набора |
| Unicode | Правила измерения кодовых единиц, code points и графем не согласованы; emoji, комбинируемые символы и Unicode-пробелы вне MVP |
| `null`, отсутствующее поле, неверный JSON-тип | DTO подсказывает ограничения, но отдельные продуктовые ожидания не согласованы; не включаем в обязательные assertions |
| Авторизация | Валидный JWT владельца — предусловие; ошибки авторизации и чужая категория не часть этого change |
| `Archived`, дубли, лимиты категорий | Существующие правила не переопределяются; использовать данные, не пересекающиеся с ними |
| Побочные эффекты | Проверяем сохранённые поля категории; требования к событиям, логам и аудиту не сформулированы |

Неоднозначные случаи требуют отдельного уточнения перед добавлением тестов.
Проверки internal REST, GraphQL и UI не входят в scope данного пилота.
