# Диагностика

До изменений сохраните команду, scope, версии, фазу падения, traceback и доступные
артефакты. Для CI-падения сначала изучите лог соответствующего запуска.

Разделяйте: дефект теста, продукта, окружения, данных и предполагаемую нестабильность.
- Setup: проверьте интерпретатор, dependencies, browser mode; remote URL не печатайте.
- Jenkins: Python 3.14 / musl и remote WebDriver; локального браузера код не требует.
- Actions: Python 3.13 и локальный Chrome/Firefox.
- UI: locator, ожидание, actual/expected и ru/en локаль; изучите Page Object.
- Данные: наличие фиксированного аккаунта и сохранённые регистрации.
- Call failure: проверьте реальные artifacts/*.png/html и Allure attachments.
  При setup/teardown hook скриншотов не срабатывает.

Не удаляйте remote wiring и не меняйте стек для обхода инфраструктурной ошибки.
Не запускайте бесконечные повторы; для гипотезы flake задайте ограниченное число
повторов и сравните свидетельства. Подтверждённый test defect исправьте минимально,
затем повторите тот же scope. Для продуктового дефекта не подгоняйте expected result.

[Ретроспектива проекта](../../docs/retrospective.md) содержит причины этих ограничений.
